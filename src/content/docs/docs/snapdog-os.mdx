**SnapDog OS** is a custom, minimal Buildroot-based Linux distribution that turns a Raspberry Pi with an I2S soundcard (DAC) into a dedicated, appliance-like audio receiver. It boots in seconds, connects to your network automatically, and requires zero command-line configuration. The Pi plays as a SnapDog client, and it can also run a SnapDog server itself (off by default, switched on in the Web UI).

<Aside type="caution">
  **Beta Release:** SnapDog OS is currently under active development. For production installations, we recommend using standard Raspberry Pi OS with the SnapDog `.deb` client package.
</Aside>

---

## Supported Hardware

SnapDog OS is compiled as a 64-bit (`aarch64`) image running a minimal Linux 6.6 LTS kernel. The following boards are fully supported:
* **Raspberry Pi 5**
* **Raspberry Pi 4**
* **Raspberry Pi 3**
* **Raspberry Pi Zero 2 W**

## 1. Installation & First Boot

### SnapDog OS Installer

[SnapDog OS Installer](https://github.com/SnapDogRocks/snapdog-os-installer) is the recommended guided installation path for macOS, Windows, and Linux. This purpose-built native application presents the supported Raspberry Pi models and release channels in one place, downloads the correct image, writes it to the selected SD card, and verifies the result.

![SnapDog OS Installer showing the Raspberry Pi model, version, target, and flash steps](/installation/snapdog-os-installer.png)

<InstallerDownloads />

Then:

1. Install or launch SnapDog OS Installer.
2. Choose your exact Raspberry Pi model.
3. Select **Stable** for normal use or **Beta** to test the newest build, then choose the offered version.
4. Click **Select target**, choose the SD card, and click **Flash!**.
5. Wait for writing and verification to finish before removing the card.

<Aside type="caution">
  Flashing erases the selected drive. Check its name and capacity before confirming.
</Aside>

### Manual Image Download
If you prefer another image writer, download the board-specific image:

| Hardware Board Model | Target Architecture | Latest Stable Image |
|---|---|---|
| **Raspberry Pi 5** | 64-bit (`aarch64`) | [Download Image (.img.gz)](https://updates.snapdog.cc/os/images/snapdog-os-pi5-release.img.gz) |
| **Raspberry Pi 4** | 64-bit (`aarch64`) | [Download Image (.img.gz)](https://updates.snapdog.cc/os/images/snapdog-os-pi4-release.img.gz) |
| **Raspberry Pi 3** | 64-bit (`aarch64`) | [Download Image (.img.gz)](https://updates.snapdog.cc/os/images/snapdog-os-pi3-release.img.gz) |
| **Raspberry Pi Zero 2 W** | 64-bit (`aarch64`) | [Download Image (.img.gz)](https://updates.snapdog.cc/os/images/snapdog-os-zero2w-release.img.gz) |

### Flashing a Manually Downloaded Image
1. Download the appropriate image file from the table above.
2. Open **Raspberry Pi Imager**.
3. Under **OS**, choose **"Use custom"** and select the downloaded `.img.gz` file.
4. Select your SD card and write.

<Aside type="caution">
  **CLI Warning:** If flashing via `dd` in the terminal, double-check your output target (`of=/dev/sdX` or `/dev/rdiskN`) to prevent overwriting your main system drive.
</Aside>

### Setting Up Wi-Fi & Initial Boot
1. Insert the written SD card into your Raspberry Pi and power it on.
2. If no working network (wired **or** wireless) is found on boot, the board automatically spawns a setup Wi-Fi network:
   * **SSID:** `SnapDog-XXXX` (where `XXXX` is the last 4 characters of the device's MAC address).
   * **Password:** a unique passphrase generated on first use, persisted on the device, and printed to the HDMI/serial console. It can be changed later in the Web UI.
3. Connect to the setup Wi-Fi using your phone or laptop.
4. Your device will automatically open a **Captive Portal** configuration wizard.
5. Enter your home Wi-Fi details, select your SnapDog server (auto-discovered via mDNS), and select your I2S DAC model. Click **Save**—the Pi will reboot and join your home network.

<Aside type="note">
  For manual client targeting, setting audio latency offsets, or choosing a soundcard (`default`, an index from `--list`, or part of the device name; ALSA names such as `hw:1` do not work) using the command-line utility directly, consult the [CLI Reference](/docs/cli#2-snapdog-client).
</Aside>

## 2. Web UI Device Management

Once the Pi is connected to your local network, you can access the configuration dashboard at `http://<hostname>.local` (or via its IP address) on port `80`. The interface is served by a lightweight Rust Axum daemon called `snapdog-ctrl`:

* **Dashboard:** Live view of the client hostname, network connections, system load, and uptime.
* **Network:** Change between Wi-Fi and Ethernet configurations, configure static IPs, or join new wireless networks.
* **Audio:** Select your I2S DAC overlay (e.g., HiFiBerry, Allo Boss, JustBoom) from the visual list. 
* **Client:** Enable or disable the client, set the Host ID, choose the volume control (software, hardware DAC, none or MIDI), set the audio offset in milliseconds (to synchronize with other rooms), pick the soundcard, and choose the server by automatic discovery or by address, with a connection test.
* **Server:** Run a SnapDog server on the Pi itself. It is off by default. Once enabled, you edit zones and clients, sources and integrations in forms, or the complete configuration in an advanced TOML editor. A change is validated by the installed SnapDog binary before it is activated. If the server does not stay healthy after the restart, the previous configuration is restored automatically.
* **SSH:** Enable SSH and manage the authorized public keys.
* **Update:** Check for OTA updates, select the stable or beta channel, and set up automatic updates (see below).
* **System:** Set the timezone, read the logs, reboot, reset to factory defaults, and export or import the device settings. An import reboots the device.

A small player bar shows what is playing and lets you pause, skip, seek and change the volume.

## 3. Architecture & Security

SnapDog OS is designed as a secure, robust audio appliance.

### Partition Layout & Read-Only Rootfs
To prevent flash memory wear and SD card corruption from sudden power loss, the root filesystem is mounted strictly **read-only**. All mutable configurations are symbolically linked to a dedicated, writeable `/data` partition.

| Partition | Size | Type | Mount Point | Purpose |
|---|---|---|---|---|
| 1 | 256 MB | FAT32 | `/boot` | Bootloader, kernel, DTBs, config.txt |
| 2 | 1 GB | EXT4 | `/` (slot A) | System Root filesystem (Read-Only) |
| 3 | 1 GB | EXT4 | `/` (slot B) | Alternative Root filesystem (Read-Only) |
| 4 | 128 MB+ | EXT4 | `/data` | Persistent writable settings (Wi-Fi, updates) |

### Dual A/B System Updates (RAUC)
System updates use standard `.raucb` signed bundles:
* **Automatic Check:** If you switch on automatic updates, the device checks daily, weekly or monthly at a time you choose (in the device's timezone). Bundles are verified for signature and hardware compatibility before installation.
* **A/B Rollbacks:** Updates install to the inactive slot and boot as a one-time trial (Raspberry Pi *tryboot*). The new slot is committed only after the system comes up healthy; if it doesn't, the next boot automatically returns to the last known-good slot.

### Security Hardening
* **No Default Access:** SSH is disabled by default. When enabled, it is restricted to public-key authentication only (keys uploaded via Web UI).
* **Authentication:** The Web UI/API password is optional. When set, `snapdog-ctrl` stores a bcrypt hash and requires bearer-token authentication for protected API routes. Changing it also changes the console root password.
* **Console login:** Until you set a Web UI password, the root password on the physical console (USB serial, or HDMI with a keyboard) is `snapdog`. It does not work over the network. Switching the Web UI password off restores `snapdog`, so set a password if others can reach the device.
