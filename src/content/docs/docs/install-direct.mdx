**SnapDog** is distributed as lightweight native binaries. The current release workflow publishes Linux (x86_64, aarch64), macOS (x86_64, aarch64), and Windows (x86_64 only) artifacts. There is also a macOS menu bar app, described below.

---

## Operating System Notes

* **Linux:** The release binaries are built on Debian 12 (glibc 2.36), so they run on Debian 12 or newer and on distributions with a glibc at least that recent. ALSA is needed on the machine that plays audio, which is where `snapdog-client` runs.
* **macOS:** The menu bar app targets macOS 15 or newer (see RFC 0006 in the SnapDog repository). I could not verify a minimum macOS version for the plain `snapdog` binary.
* **Windows:** Only x86_64 builds exist. There is no ARM64 build.

## Package Managers

<Tabs>
  <TabItem label="Arch Linux (AUR)">
    The AUR packages install the prebuilt release binaries, the same ones as in the release archives, Debian packages and container images. They do not build from source.

    ```bash
    # Install the server and audio client
    yay -S snapdog snapdog-client

    # Enable and start both services (the packages install their systemd units)
    sudo systemctl enable --now snapdog snapdog-client
    ```
  </TabItem>

  <TabItem label="macOS (Homebrew)">
    For Apple Silicon or Intel Macs, there is a Homebrew tap:

    ```bash
    # Tap the repository
    brew tap snapdogrocks/tap

    # Install the server and audio client
    brew install snapdog snapdog-client

    # Run SnapDog as a macOS background service
    brew services start snapdog
    ```
  </TabItem>

  <TabItem label="Debian/Ubuntu (APT)">
    There are native `.deb` packages for Debian and Ubuntu architectures (amd64, arm64).

    1. Fetch the archive keyring and check its fingerprint before trusting it:
       ```bash
       curl -fsSL https://deb.snapdog.cc/snapdog-archive-keyring.pgp \
         -o /tmp/snapdog-archive-keyring.pgp
       gpg --show-keys --with-colons /tmp/snapdog-archive-keyring.pgp \
         | awk -F: '$1 == "fpr" { print $10; exit }'
       # Expected: 1B7B79417383648BBFBE282E01AB8296EF0FCD76
       ```
       That is the certifying primary key; packages for this domain are signed
       by its subkey `CFE7BACA652DD0D72EB7156FC7252FAD41F8F7DA`.
    2. Register the repository, bound to that key:
       ```bash
       sudo install -m 0644 /tmp/snapdog-archive-keyring.pgp \
         /usr/share/keyrings/snapdog-archive-keyring.pgp
       echo "deb [signed-by=/usr/share/keyrings/snapdog-archive-keyring.pgp] https://deb.snapdog.cc rolling main" \
         | sudo tee /etc/apt/sources.list.d/snapdog.list
       ```
    3. Update package lists and install:
       ```bash
       sudo apt update
       sudo apt install snapdog snapdog-client
       ```
    4. Enable and start both services. The packages install their own systemd
       units, so there is no unit file to write:
       ```bash
       sudo systemctl enable --now snapdog snapdog-client
       ```
    </TabItem>

  <TabItem label="Windows Service">
    SnapDog runs on Windows (x86_64 only) as a native binary and can run as an NT Service.

    1. Download the Windows archive from the [GitHub Releases](https://github.com/SnapDogRocks/snapdog/releases) page. It is a `.zip` file named like `snapdog-vX.Y.Z-x86_64-pc-windows-msvc.zip`. Extract it and place `snapdog.exe` (and `snapdog-client.exe` if you want audio output on this machine) in `C:\Program Files\SnapDog\`.
    2. Open a Command Prompt as Administrator and register the service:
       ```cmd
       sc create SnapDog binPath= "\"C:\Program Files\SnapDog\snapdog.exe\" --service --config \"C:\ProgramData\snapdog\snapdog.toml\"" start= auto
       sc start SnapDog
       ```
  </TabItem>
</Tabs>

## macOS menu bar app

Download `SnapDog-Server-*.dmg` from the [GitHub Releases](https://github.com/SnapDogRocks/snapdog/releases/latest) page. The menu bar app embeds the server binary, starts and stops it for you, and updates itself through Sparkle.

## Direct Binary Download

If you prefer to install the pre-compiled binaries manually:

1. Download the correct archive for your system from the [GitHub Releases](https://github.com/SnapDogRocks/snapdog/releases) page. Linux and macOS archives are `.tar.gz`, the Windows archive is a `.zip`. Each has a `.sha256` file next to it.
2. Extract the archive and copy the binary to `/usr/local/bin`:
   ```bash
   tar -xzf snapdog-vX.Y.Z-x86_64-unknown-linux-gnu.tar.gz
   cd snapdog-vX.Y.Z-x86_64-unknown-linux-gnu
   sudo install -m 755 snapdog snapdog-client /usr/local/bin/
   ```

Each archive contains `snapdog`, `snapdog-client`, `snapdog.example.toml`, `LICENSE`, `README.md` and a `packaging/` folder. The folder holds the systemd units, the `/etc/default` files and the D-Bus policies that the Linux packages install.

## Compiling from Source

If you want to compile SnapDog with custom target optimizations, you can build it from source using Cargo.

<Aside type="note">
  Building from source allows choosing specific Snapcast server backends. See the compilation feature flags described in the [Server Mode Selection](#server-mode-selection) section below.
</Aside>

### Build Dependencies
Ensure your development machine has the required system libraries installed:
* **Rust:** `rust-toolchain.toml` in the repository pins the exact version, and `rustup` installs it on the first build. The README states a minimum of Rust 1.94.
* **Node.js and pnpm:** `build.rs` builds the embedded web UI with `pnpm install --frozen-lockfile` and `pnpm run build`. Without a prebuilt `webui/out`, both must be installed. Setting `SKIP_WEBUI_BUILD=1` builds with a placeholder page instead of the web UI.
* **CMake:** The Docker build installs `cmake` next to the other build tools, so install it as well.
* **Debian/Ubuntu:** `sudo apt install build-essential cmake pkg-config clang libasound2-dev libavahi-compat-libdnssd-dev`
* **macOS:** Xcode Command Line Tools, plus CMake (for example `brew install cmake`).

### Building
1. Clone the repository:
   ```bash
   git clone https://github.com/SnapDogRocks/snapdog.git
   cd snapdog
   ```
2. Build the release binary:
   ```bash
   cargo build --release --locked -p snapdog
   ```
3. The compiled binary will be available at `target/release/snapdog`.

The default feature set gives you AirPlay 1 only. The release binaries are built with `--features snapdog/full`, which adds AirPlay 2 and the API documentation, next to Spotify and D-Bus:

```bash
cargo build --release --locked -p snapdog -p snapdog-client --features snapdog/full
```

## Post-Installation Service Scripts

This section is only for the [direct binary download](#direct-binary-download) and [source builds](#compiling-from-source). The AUR and APT packages install their own systemd units, and Homebrew runs SnapDog through `brew services`.

<Aside type="caution">
  Do not add these files on a package install. A unit in `/etc/systemd/system/` overrides the one the package installed, and this one points to `/usr/local/bin` instead of `/usr/bin`.
</Aside>

### Linux Systemd Service Unit
Create `/etc/systemd/system/snapdog.service`. This is the unit the packages ship (`snapdog/systemd/snapdog.service` in the repository), with the binary in `/usr/local/bin`:

```ini
[Unit]
Description=SnapDog multiroom audio server
After=network-online.target sound.target
Wants=network-online.target

[Service]
Type=simple
EnvironmentFile=-/etc/default/snapdog
ExecStart=/usr/local/bin/snapdog $SNAPDOG_ARGS
Restart=on-failure
RestartSec=5
DynamicUser=yes
SupplementaryGroups=audio
StateDirectory=snapdog
LogsDirectory=snapdog
LogsDirectoryMode=0750
WorkingDirectory=/var/lib/snapdog
ConfigurationDirectory=snapdog
ProtectSystem=strict
ProtectHome=yes
NoNewPrivileges=yes
PrivateTmp=yes
AmbientCapabilities=CAP_NET_BIND_SERVICE
CapabilityBoundingSet=CAP_NET_BIND_SERVICE

[Install]
WantedBy=multi-user.target
```

The unit reads its arguments from `/etc/default/snapdog`. Create that file (the `packaging/` folder of the release archive has an example):

```bash
echo 'SNAPDOG_ARGS="--config /etc/snapdog/snapdog.toml"' | sudo tee /etc/default/snapdog
```

`CAP_NET_BIND_SERVICE` lets AirPlay 2 bind UDP 319 and 320 as the unprivileged service user. Without it AirPlay 2 still works, but every connect starts slower.

Then load and start it:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now snapdog
```

For the audio client, use [`snapdog-client.service`](https://github.com/SnapDogRocks/snapdog/blob/main/snapdog-client/systemd/snapdog-client.service) from the repository the same way and change its `ExecStart` to `/usr/local/bin/snapdog-client`.

### macOS Launchd Service Agent
Create `~/Library/LaunchAgents/cc.snapdog.server.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>cc.snapdog.server</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/local/bin/snapdog</string>
        <string>--config</string>
        <string>/Users/Shared/snapdog.toml</string>
    </array>
    <key>RunAtLoad</key>
    <true/>
    <key>KeepAlive</key>
    <true/>
</dict>
</plist>
```

## Server Mode Selection

SnapDog can be built with one of two Snapcast backends. You select the backend with Cargo feature flags:

* **`snapcast-embedded` (default, and the engine in the releases):** The Snapcast server is part of the SnapDog binary, using the `snapcast-*` Rust crates. No external program is needed.
* **`snapcast-process`:** Spawns and manages a standalone C++ `snapserver` process. The two backends exclude each other, so build it with:
  ```bash
  cargo build --release --locked -p snapdog --no-default-features --features snapcast-process
  ```
  This also drops the default `spotify` and `dbus` features, because `--no-default-features` removes them. Released binaries use the embedded server only.
