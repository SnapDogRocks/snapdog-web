This guide documents the command-line interfaces for both the **SnapDog Server (`snapdog`)** and the **SnapDog Client (`snapdog-client`)**.

---

## 1. SnapDog Server

The `snapdog` server runs as a daemon that manages audio streams, routes signals to zones, and acts as the central coordinator.

<Aside type="note">
  For running the server as a background service supervised by systemd or launchd, see the [Direct Installation Guide](/docs/install-direct#post-installation-service-scripts).
</Aside>

### Required Execution Modes

At startup, the server requires you to declare its primary configuration mode. You **must** specify either `--config` or `--knx-device`.

* **Configuration File Mode:** Standard operation using a TOML file.
  ```bash
  snapdog --config /path/to/snapdog.toml
  ```
* **KNX Device Mode:** Bootstraps with standard defaults and relies on an ETS (Engineering Tool Software) project download over KNX routing/tunneling to configure zones and group addresses.
  ```bash
  snapdog --knx-device
  ```

<Aside type="danger">
If neither `--config` nor `--knx-device` is specified, the server prints the help guide and exits immediately with status code `1`.
</Aside>

### Server Arguments Reference

| Option | Shorthand | Type | Description |
| :--- | :--- | :--- | :--- |
| `--config <PATH>` | `-c` | String (Path) | Path to the TOML configuration file. |
| `--check-config` | — | Flag | Validates the configuration, prints warnings, the network interfaces of the host and the planned listeners, then exits without starting any service. *(Requires `--config`)* |
| `--webui <current\|legacy>` | — | String | Chooses the web interface served at `/` for this run (TOML: `[http].webui`, default `current`). |
| `--knx-device` | — | Flag | Enables KNX Device mode, causing the server to register as an ETS-programmable device. |
| `--knx-address <ADDR>` | — | String | The KNX physical address (e.g. `1.1.100`) to advertise in ETS. Defaults to `15.15.255`. *(Requires `--knx-device`)* |
| `--knx-prog-mode` | — | Flag | Starts the server with KNX programming mode active immediately. *(Requires `--knx-device`)* |
| `--knx-sync-system-clock` | — | Flag | Lets the KNX Time group object set the operating system clock (best effort, needs privileges). TOML: `[knx].sync_system_clock`. |
| `--port <PORT>` | `-p` | Integer | Overrides the HTTP API / WebUI listening port (TOML: `[http].port`). |
| `--bind <ADDR>[,<ADDR>...]` | `-b` | String list | Overrides the HTTP bind address (TOML: `[http].bind`). Takes one address (e.g. `::`, `0.0.0.0`, or a concrete interface IP) or several, separated by commas. |
| `--tls-cert <PATH>` | — | String (Path) | Path to a PEM certificate chain to enable HTTPS/TLS. |
| `--tls-key <PATH>` | — | String (Path) | Path to an unencrypted PEM private key for HTTPS/TLS. |
| `--codec <CODEC>` | — | String | Snapcast stream codec. It overrides `[snapcast].codec`. Options: `pcm`, `flac`, `f32lz4`, `f32lz4e`. |
| `--sample-rate <HZ>` | — | Integer | Output sample resampling frequency (e.g., `44100`, `48000`, `96000`). |
| `--bit-depth <BITS>` | — | Integer | Output audio PCM bit depth. Options: `16`, `24`, `32`. |
| `--streaming-port <PORT>` | — | Integer | Port for client speaker connections (TOML: `[snapcast].streaming_port`). |
| `--name <NAME>` | — | String | Overrides the server name. It is the mDNS instance name, the Home Assistant device name and the name in the `/system/version` endpoint. |
| `--log-level <LEVEL>` | `-l` | String | Log level verbosity. Options: `trace`, `debug`, `info`, `warn`, `error`. |
| `--service` | — | Flag | Runs the binary as a native NT Service. *(Windows builds only)* |

Command-line values override the configuration file. After the overrides are applied, SnapDog validates the result like file values. For example, `--sample-rate 32000` stops the start with a message, because only `44100`, `48000`, `88200`, `96000`, `176400` and `192000` are accepted.

### Server Boot Examples

<Tabs>
  <TabItem label="Standard Daemon Mode">
    Launch the server on Linux or macOS with a specific configuration file:
    ```bash
    snapdog --config /etc/snapdog/snapdog.toml
    ```
  </TabItem>

  <TabItem label="Debugging & Port Override">
    Temporarily override the web server port and increase logging verbosity to debug connection issues:
    ```bash
    snapdog --config ~/.config/snapdog.toml --port 8080 --log-level debug
    ```
  </TabItem>

  <TabItem label="Check a Configuration">
    Validate a file before you restart the service. The command exits with status `0` when the file is fine:
    ```bash
    snapdog --config /etc/snapdog/snapdog.toml --check-config
    ```
  </TabItem>

  <TabItem label="KNX Integration Bootstrapping">
    Launch in device mode to let an integrator assign a physical address (e.g., `1.1.25`) and program the server using the `.knxprod` file:
    ```bash
    snapdog --knx-device --knx-address 1.1.25 --knx-prog-mode
    ```
  </TabItem>
</Tabs>

## 2. SnapDog Client

The `snapdog-client` player runs on speaker endpoints, connecting back to a SnapDog server to pull and play synchronized PCM audio.

### Server Connection URL

The client takes an optional positional argument specifying the server connection string:
```bash
snapdog-client [URL]
```
Only `tcp://` URLs work. The format is `tcp://[user:password@]<host>[:port]`, and the port defaults to `1704`. The client rejects `ws://` and `wss://` URLs.
* **mDNS Discovery (Default):** If you leave out the URL, the client browses the local network for a `_snapdog._tcp` service for 5 seconds and connects to the server it finds.
* **Direct TCP Socket:** Connects directly to the stream socket (e.g. `tcp://192.168.1.50:1704`).

### Client Arguments Reference

| Option | Shorthand | Type | Description |
| :--- | :--- | :--- | :--- |
| `[URL]` | — | Positional | Connection URL, `tcp://` only. Without it, the client finds a server through mDNS. |
| `--instance <ID>` | `-i` | Integer | Instance ID when running multiple client players on the same host (default: `1`). |
| `--hostID <ID>` | — | String | Unique host identifier. Defaults to the network card's MAC address. |
| `--soundcard <DEVICE>` | `-s` | String | Audio output device. Use `default`, an index from `--list`, or part of a device name or id as `--list` prints it (case does not matter). ALSA names such as `hw:1` do not work and abort the start. Defaults to `default`. |
| `--list` | `-l` | Flag | Lists all available local PCM soundcard output devices and exits. |
| `--test-tone` | — | Flag | Plays a brief audio test tone and exits to verify soundcard output. |
| `--latency <MS>` | — | Integer | Manual latency offset in milliseconds to align with laggy hardware (default: `0`). |
| `--player <BACKEND>` | — | String | Only `null` has an effect: it discards the audio and opens no device. Any other value is ignored with a warning, because playback always uses the system audio output. Choose the device with `--soundcard`. |
| `--mixer <MODE>` | — | String | Volume mixer mode: `software` (default), `hardware:<control>`, `midi:<interface>:<ch>[:<cc>]`, `x32:<host>:<ch>[,<ch>][:<port>]` or `none`. See below. |
| `--mixer-sync <MODE>` | — | String | Which way volume flows with a mixer that reports its own changes (only `x32` so far). `both` (default): the server sets the mixer and changes at the mixer go back to the server. `out`: the server sets the mixer and changes at the mixer stay until the next server volume. |
| `--encryption-psk <KEY>`| — | String | Pre-shared key for stream decryption when using `f32lz4e`. Without it, the built-in key is used. |
| `--daemon [PRIORITY]` | `-d` | Integer | Run in the background (daemonized) with an optional process priority `[-20..19]`. Without a value the priority is `-3`. *(Unix only)* |
| `--logsink <SINK>` | — | String | Log output target: `null`, `stdout` (default), `stderr`, `file:<path>` or `system`. `system` writes to stderr, not to syslog. |
| `--logfilter <FILTER>`| — | String | Log tag levels filter (default: `*:info`, e.g. `*:debug`). |

<Aside type="note">
The client has a few hidden or compatibility options that do nothing. `--sampleformat` is ignored because the output follows the stream's format. `--cert`, `--cert-key`, `--key-password` and `--server-cert` are ignored because TLS is not available, and the client connects over plain `tcp://`. `--user` is refused, so run the client as the user you want, as the shipped systemd unit does with `DynamicUser=yes`.
</Aside>

<Aside type="tip">
**Mixer Modes:**
* `software` (Default): Digital volume scaling of the incoming PCM buffer.
* `hardware:<control>`: Calls ALSA's mixer interface to set physical soundcard gain (e.g. `--mixer hardware:Master` or `--mixer hardware:Speaker`).
* `midi:<interface>:<ch>[:<cc>]`: Maps incoming volume levels to a MIDI CC control message. The CC number is optional and defaults to CC7.
* `x32:<host>:<ch>[,<ch>][:<port>]`: Drives the channel fader of a Behringer X32 over OSC, with the same scale as `midi`. Use `--mixer-sync` to choose whether changes at the desk go back to the server.
* `none`: Disables volume adjustments on the client.
* `script` is not implemented. The client falls back to `software` and prints a warning.
</Aside>

### Client Boot Examples

<Tabs>
  <TabItem label="Standard Auto-Discovery">
    Start playing. Searches network for a SnapDog server automatically:
    ```bash
    snapdog-client
    ```
  </TabItem>

  <TabItem label="Hardware Mixer Control">
    Directly target a server IP and utilize ALSA physical card mixers to control volume. `DAC` stands for any part of a device name that `--list` prints:
    ```bash
    snapdog-client --soundcard DAC --mixer "hardware:Digital" tcp://192.168.1.100:1704
    ```
  </TabItem>

  <TabItem label="Diagnostics Check">
    List all local audio output devices, then run a test sound on the device with index `1` from that list:
    ```bash
    snapdog-client --list
    snapdog-client --soundcard 1 --test-tone
    ```
  </TabItem>

  <TabItem label="Encrypted Stream (PSK)">
    Decrypt a stream that the server sends with `codec = "f32lz4e"`, using the same pre-shared key as `[snapcast].encryption_psk`:
    ```bash
    snapdog-client --encryption-psk "my_secret_key" tcp://192.168.1.100:1704
    ```
  </TabItem>
</Tabs>
